# Реален учебен цикъл — проверка на 8 септември 2026

**Резултат: успешно.** Един интеграционен браузърен тест изпълни пълния цикъл за два вида задания: мисия от учебната програма и собствена учителска задача. Успешното изпълнение отне 17.9 секунди.

## Среда и обхват

- Локална production сглобка на приложението, `http://127.0.0.1:3101`.
- Реалният Supabase проект `hmhwupoubtdcywcsqtwz` („Learning lessons“), с всички 48 локални миграции до `20260904120000`.
- Отделни Chromium контексти за временен учител, ученик и чужд учител.
- Реален вход с имейл и парола през интерфейса. Няма fake-auth cookie, подменени API отговори или подменени записи за заданията.
- Временните Auth акаунти/идентичности и началните им роли бяха подготвени като SQL fixtures. Самата регистрация, email confirmation и административното даване на teacher роля не са предмет на този тест.
- Класът, членството, заданията, предаванията и ревютата са създадени през реалните интерфейс и API. Допълнителните проверки на данните използват потребителски Supabase сесии, не service-role достъп.

Това доказва потока на текущия локален код срещу реалната база. Не е тест на публикувания Vercel deployment, мобилния изглед, AI генериране, co-teacher права, срокове или работа при едновременни предавания.

## Проверки за отказ

Изпълнени и за двата типа задачи:

- Ученик опитва да одобри собственото си предаване → HTTP 403.
- Учител извън класа опитва да одобри → HTTP 403.
- Чуждият учител чете предаването директно през Data API → празен резултат по RLS.
- Ученик опитва да презапише работа със статус `submitted` → HTTP 409; оригиналният текст остава.
- Ученик опитва да презапише работа със статус `approved` → HTTP 409; одобреният текст остава.

Не са засечени необработени JavaScript грешки в страниците при успешното изпълнение.

## Независима проверка в базата

След браузърния тест отделна SQL заявка потвърди за всяка задача:

- точно един submission запис;
- краен статус `approved` и текстът от второто предаване;
- три запазени събития в private историята: `teacher_review / needs_changes`, `cleared_on_resubmit / needs_changes`, `teacher_review / approved`;
- оригиналната учителска бележка и първият текст са запазени в историята.

Идентификатор на проверката: `86e9b7e1-1140-444d-9823-17c61e9b1a6d`.

## Почистване

След проверката са премахнати временните класове, акаунти, профили, сесии, задания, предавания и свързаната история. Независимата проверка след почистване върна **0** останали записа във всяка от тези групи за тестовите идентификатори.

Не е променян продуктов код или схема на базата за тази проверка. Коригирани бяха две предположения в новия тест: join code се чете през `get_teacher_classroom`, а формата за присъединяване трябва да бъде отворена от свитата секция.

## Повторно изпълнение

Тестът е отделен от стандартните E2E сценарии:

- Конфигурация: `playwright.live.config.ts`.
- Сценарий: `integration/classroom-cycle.spec.ts`.
- Артефакти: `test-results/live-cycle/`, включително `evidence.json` и снимки на върнатата и одобрената работа.

Необходими са три отделни временни Auth акаунта в избраната база и JSON файл извън git с права `0600`:

```json
{
  "runId": "<unique-run-id>",
  "users": [
    {"kind":"teacher","id":"<auth-user-id>","email":"ll-live-<unique-run-id>-teacher@example.invalid","password":"<temporary-password>","name":"Live Cycle teacher"},
    {"kind":"student","id":"<auth-user-id>","email":"ll-live-<unique-run-id>-student@example.invalid","password":"<temporary-password>","name":"Live Cycle student"},
    {"kind":"outsider","id":"<auth-user-id>","email":"ll-live-<unique-run-id>-outsider@example.invalid","password":"<temporary-password>","name":"Live Cycle outsider"}
  ]
}
```

Учителят и outsider акаунтът трябва да имат `profiles.role = teacher`, ученикът — `user`. Имената в JSON трябва да съответстват на профилите. Използват се само отделни тестови идентичности. Приложението трябва да е изградено с публичните ключове на същия Supabase проект.

```bash
npm run build
LIVE_CYCLE_CREDENTIALS_FILE=/absolute/private/path/credentials.json npx --no-install playwright test --config=playwright.live.config.ts
```

Тестът създава реални записи и не се пуска автоматично от `npm test` или стандартния `test:e2e`. Той затваря браузърите и отписва допълнителните сесии. Изтриването на временните акаунти и данни е отделна операторска стъпка: използвайте точните Auth ID и run ID, почистете класа и свързаните записи, профилите и Auth акаунтите, и проверете нулев остатък. Никога не използвайте широко изтриване по произволен имейл префикс.
